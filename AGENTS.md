## Железные правила

- **План до кода.** Нетривиальная задача начинается с плана, который человек одобрил словами.  <!-- aqk: человек -->
- **Красный тест до кода.** Сначала проверка, которая падает, потом реализация.  <!-- aqk: человек -->
- **Максимум 3 попытки.** Не решил за три — стоп и человеку, а не четвёртый заход.  <!-- aqk: человек -->
- **Секреты только в окружении.** Никогда в коде, логах и коммитах.  <!-- aqk: secrets-not-in-code -->
- **Только файлы из задачи.** Заодно ничего не чиним.  <!-- aqk: человек -->
- **Готово = доказано.** Назови арбитра: тест, живой прогон, сверка с источником. «Выглядит  <!-- aqk: человек -->
  рабочим» — не готово.
- **Ошибку не глотать.** Либо обработана и залогирована, либо проброшена.  <!-- aqk: человек -->
- **Развилка — вопрос человеку.** Отступление от принятого решения не оформляется комментарием  <!-- aqk: человек -->
  в коде.
- **Отчёт о работе с комплектом — командой, а не словами.** Закончил — выполни `aqk report`.  <!-- aqk: человек -->
  Он собирается прогоном: пересказ по памяти всегда выбирает удобное и молчит о том, что гейт
  стоит на слабейшем рецепте.

## Оснастка AQK — это твои команды, а не человека

В репозитории стоит комплект AQK. Его смысл: **обещание проекта превращается в команду с кодом
возврата**, и дальше его держит машина, а не чья-то внимательность. «Не оставляем отладочную
печать» — текст, который можно проигнорировать; команда, возвращающая не ноль, — нельзя.

Запускать их — твоя работа. Человек смотрит на список дыр и решает, какие закрывать.

| Команда | Что делает | Когда звать |
|---|---|---|
| `aqk doctor` | смотрит репозиторий и печатает три списка: что уже держит машина, чего не хватает, что этому проекту не нужно и почему | начало работы над качеством; «что тут вообще есть» |
| `aqk doctor --run` | **запускает** объявленные проверки и показывает, кто нашёл брак | перед сдачей; после правок; всегда, когда нужен факт, а не обещание |
| `aqk add <имя>` | ставит проверку из каталога: копирует её и образцы в проект, объявляет в манифесте | человек согласился закрыть дыру из списка `doctor` |
| `aqk ratchet <имя>` | старые нарушения записывает долгом, новые перестаёт пускать | проверка краснеет на старом коде, и чинить его сейчас никто не будет |
| `aqk find "…"` | ищет по смыслу, есть ли уже такая проверка | прежде чем изобретать свою |
| `aqk note "…"` | пишет урок в общий журнал | процесс или прибор подвели: проверка соврала, правило обошли |
| `aqk report` | собирает прогоном отчёт: что стоит и каким рецептом, чего нет, что комплект велел прочитать | **обязательно** в конце работы с комплектом — вместо пересказа по памяти |
| `aqk badge` | печатает значок уровня для README — но только после прогона объявленных гейтов, а при красном молчит; `--check` роняет конвейер, когда значок разошёлся с прогоном | человек попросил показать уровень; настраиваешь конвейер |

Если команды `aqk` нет в системе — комплект ставили разово, без установки. Тогда вместо
`aqk` пиши `npx agent-quality-kit`. Любая команда сама печатает тот
вызов, который сработает у тебя.

**Три вещи, которые надо понимать, а не запоминать:**

1. **«Объявлен» и «работает» — разные утверждения.** `doctor` без `--run` честно говорит, что
   проверки не запускал. Не выдавай объявленное за работающее.
2. **Проверка без двух образцов ничего не доказывает.** Красный — код, на котором она обязана
   сработать; зелёный — правильный, на котором обязана молчать. Зелёный важнее: без него однажды
   она покраснеет на верном коде, и её выключат вместе с остальными.
3. **Правило вводится храповиком, а не большой чисткой.** Чистка откладывается навсегда, потому
   что она большая. Храповик даёт действующее правило со дня установки.

**Повторился дефект того же класса — это не повод быть внимательнее, а повод завести проверку.**
Дисциплина не масштабируется, механика — да.

## Чужой код в репозитории

Код, который лежит здесь, но написан не здесь (референс, вендоринг, генерация),
исключается файлом `.aqkignore` в корне — по шаблону на строку. Правка копии `_skip.sh`
не настройка: её затрёт следующий `aqk add`.

## Где что лежит

- `.aqk/rules/` — стандарты: общие, тесты, безопасность
- `.aqk/docs/` — методички: минимум проекта, харнес, процесс, исследования (в репозитории не хранятся — это общий текст комплекта; разложить у себя: `npx agent-quality-kit init`)
- `.aqk/docs/project-baseline.md` — **начни отсюда**, если проект новый
- `.aqk/skills/README.md` — чужие скиллы: что посмотреть, что НЕ ставить и почему.
  Ставить не всё: решение твоё, и перед установкой читается живая версия по ссылке, а не наша
  строка — она снимок

## Команды

<!-- Заполни под свой проект. Команда, которую нельзя скопировать и выполнить, — не команда. -->

- сборка установщика: `.venv\Scripts\python.exe installer\build.py` → `installer/out/Keeper-Setup-<версия>.exe` (нужен Inno Setup 6; версия — из `extension/manifest.json`)
- тесты: `bash tests/run.sh` (Python и, если есть Node, логика потоков расширения — `tests/extension`)
- сквозной тест расширения (нужны запущенная качалка и Node): `cd tests/e2e && npm install && npm test`
- то же в Edge или Яндекс Браузере: перед командой задать `BROWSER_EXE` — путь к `msedge.exe` или `browser.exe`; запуск программы самим браузером проверяет `node start.mjs` (программа при этом должна быть закрыта)
- линтер: `ruff check --isolated --select F,BLE,C901,PLR0912,PLR0915,T20 server.py launcher.py kachalka tests`
- всё разом перед пушем: `bash tests/run.sh && npx --yes agent-quality-kit@0.19.0 doctor --run`
- запустить качалку вручную: `start.bat` (обычно её поднимает само расширение через `launcher.py`)

## Чего в этом проекте нет

<!-- Пиши сюда честно. Ненаписанное «нет» агент додумает как «есть». -->

- Установщик собирается только руками на Windows и не подписан: Windows при запуске предупреждает о неизвестном издателе. Готовый файл в git не лежит.
- Два способа установки живут рядом: установщик (свой Python и ffmpeg в папке программы) и копия из репозитория (`install.bat`, окружение `.venv`). Правка запуска должна работать в обоих — см. `launcher.runtime` и `system.find_ffmpeg`.
- Нет линтера для JavaScript расширения (`eslint` не стоит). Тестами покрыта только логика потоков (`extension/streams.js`); фон и окно — сквозным тестом.
- Нет автотестов для ветки GetCourse (плеер, страница урока): нужен настоящий урок с входом.
- Сквозной тест расширения не идёт в конвейере — только руками, на Windows с запущенной качалкой.
- Работает только на Windows: трей, уведомления, вывод окон вперёд, запуск из браузера. Браузеры — Chrome, Edge, Яндекс Браузер; Firefox и Opera не поддерживаются.
- Распознавание речи — только русский (GigaAM v3) и языки Parakeet v3 (английский и 24 европейских); разделения по говорящим нет.
- Модели распознавания (`models/`, ~860 МБ) в репозитории не лежат: качалка скачивает их сама при первом использовании.
- Автотестов самого распознавания нет (нужны модели и ffmpeg): проверяется вручную на настоящей записи.
